# 0003: Оценки v2 — пять объяснимых факторов вместо одного числа
Status: Proposed
(Не принято. Решение вступает в силу только после одобренного слияния этого PR координатором.)

## Context
Сейчас `catalog/build_catalog.py` выдаёт `significance` и `interest` (0..100), список `danger_flags`
и `tier`. Это эвристики, на исходах они не проверялись. Найденные проблемы:
- Неизвестное неотличимо от нуля: `interest` по умолчанию 0 (у акций, бирж и медиа данных нет),
  у проекта без TVL значимость становится 0, у биржи без trust score — тоже 0.
- Отсутствие сведений превращается во флаг («аудит не указан») или в тишину (нет флагов
  выглядит как «чисто»). Доказанной безопасности источники не дают никогда.
- Нет доверия к записи, нет времени наблюдения и нет источника у каждого числа
  (есть только строка `extra` и `origin`).
- У акций значимость — позиция в списке SEC, а не размер компании: это прокси.
Подробности, формулы и примеры: `docs/SCORING.md`.

## Decision (предложение)
1. Пять факторов: `significance`, `interest`, `danger`, `trust`, `freshness`. Каждый имеет значение 0..100
   или `null`, состояние `known | unknown | stale` и список входов с источником и временем наблюдения.
2. Отсутствие данных — `unknown` (`null`), а не 0. Для `danger` три разных состояния:
   `flagged`, `no_flags_seen` (флаги не найдены), `unknown`. Состояния «безопасно» нет.
3. Единого итогового балла нет. Для сортировки допустим `attention = max(значимость, интерес)` по
   факторам в состоянии `known`; нет таких — `null`. Это порядок показа, а не оценка и не совет.
4. Текущие `significance`, `interest`, `danger_flags` и API R02 не меняются. v2 — отдельный объект
   `scores_v2`, который добавит R05B после слияния #10 и принятия этого решения.
5. Это эвристики с объяснением, а не проверенная статистическая модель. Без разметки исходов
   их нельзя выдавать за прогноз. Никаких buy/sell советов.

## Consequences
- UI и R05B смогут показывать причину каждого числа и честно писать «нет данных».
- Нужны новые входы: время наблюдения каждой записи и источник по каждому числу. Это работа
  сборщика каталога (вне R02); R02 их не обязан хранить. Пока их нет, `freshness` = `unknown`.
- Больше полей и состояний; потребители обязаны обрабатывать `null`.
- Рассмотренные альтернативы — в `docs/SCORING.md`.
