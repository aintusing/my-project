# Оценки v2: контракт факторов (предложение)

Статус: проект к решению 0003 (Proposed). Не меняет `docs/API.md`, `catalog/db/`, `radar/api/`,
текущие баллы и данные. Реализация и тесты — отдельная задача R05B после слияния #10 и принятия 0003.
Все числа ниже — эвристики для сортировки, на исходах не проверялись. Это не прогноз и не совет.

## 1. Что есть сейчас (по `catalog/build_catalog.py`)
| Поле | Как считается | Проблема |
| --- | --- | --- |
| `significance` | монета: 0.6·ранг по капитализации + 0.4·объём; проект: log TVL; биржа: trust·10; фиды 70/55/50; акция: позиция в списке SEC | нет данных = 0; у акций это прокси, не размер |
| `interest` | монета: 1.5·\|7д\| + 60·оборот; проект: 2·\|7д\|; у остальных 0 | 0 означает и «спокойно», и «не знаем» |
| `danger_flags` | текстовые признаки из правил источника | отсутствие данных (аудит не указан) стало флагом; пустой список читается как «чисто» |
| `tier` | S/A/B/C по рангу внутри набора | зависит от набора, не от записи |
Времени наблюдения и источника у каждого числа нет (только `origin` и строка `extra`).
Ограничения источников: бесплатные лимиты CoinGecko, SEC может отвечать 403 без нужного User-Agent
(так было при сборке R02), списки угроз — не источники активов.

## 2. Факторы
Единицы: целое 0..100 или `null`. Состояние: `known` (есть свежие входы), `unknown` (нет входов),
`stale` (входы старше `ttl`; значение показывается, но помечено).
| Фактор | Смысл | Нужные входы | Правило |
| --- | --- | --- | --- |
| `significance` | заметность и размер | капитализация/TVL/объём/ранг, trust биржи | формулы §1 без замены пропусков нулём; нет входов → `unknown`; прокси помечается `basis: proxy` |
| `interest` | насколько сейчас движется | изменение за 7д, оборот | как §1; нет рядов цены → `unknown` |
| `danger` | сколько конкретных признаков найдено | флаги с весами (§3) | сумма весов, максимум 100; состояние отдельное (§3) |
| `trust` | насколько запись подтверждена данными, не безопасность | обязательные поля записи, число независимых источников | `100 · доля_полей · k`; k=1.0 (≥2 источника), 0.7 (один), 0.4 (ручной/непроверенный) |
| `freshness` | свежесть входов | `observed_at` самого старого входа | возраст ≤ ttl → 100; иначе `100·(1−(возраст−ttl)/(2·ttl))`, не ниже 0; > ttl → `stale` |
ttl по умолчанию: рынок 24 ч, реестры (SEC, ручной список) 7 дней. Нет `observed_at` → `freshness=null`, `unknown`.

## 3. Опасность: три разных состояния
- `flagged` — есть хотя бы один признак с источником.
- `no_flags_seen` — входы были, признаков не найдено. Это не «безопасно»: источники конечны.
- `unknown` — входов для проверки нет. Отсутствие данных НЕ становится флагом.
Веса (эвристика): совпадение с санкционным списком 100; совпадение в списке угроз 50 за независимый
список; взлом в истории 30; прочие признаки каталога 15. Итог = min(100, сумма).
Адреса и домены из списков угроз не показываются ссылками и не открываются; в результате только счётчик
и название списка.

## 4. Итоги
Единого балла нет. Порядок показа: `attention = max(significance, interest)` по факторам в состоянии
`known`; записи с `stale` или `null` идут после свежих. Альтернатива «взвешенная сумма» отклонена (§7).

## 5. Форма результата (будущая, добавит R05B)
```
"scores_v2": {
  "version": 2,
  "significance": {"value": 57, "state": "known", "basis": "rank+volume",
    "inputs": [{"field": "market_cap_rank", "value": 40, "source": "CoinGecko", "observed_at": "<ISO UTC>"}]},
  "interest": {...}, "trust": {...}, "freshness": {...},
  "danger": {"state": "no_flags_seen", "value": null, "flags": [{"id": "...", "weight": 15, "source": "..."}]},
  "attention": 57
}
```
`value` — `null`, когда состояние `unknown`. Для `danger` значение задано только при `flagged`.

## 6. Совместимость и входы от R02
- Старые `significance`, `interest`, `danger_flags`, `tier` остаются как есть; v2 рядом, не вместо.
- Потребителям API R02 ничего не нужно менять. `scores_v2` — отдельное расширение; контракт
  R02 (`docs/API.md`) его не требует и не блокируется.
- Желательные будущие входы (не для R02, а для сборщика каталога): `observed_at` на запись и
  источник по каждому числу. До тех пор `freshness` = `unknown`. R02 хранит `origin` и `extra` — пока достаточно.

## 7. Примеры (СИНТЕТИЧЕСКИЕ, придуманы для разбора, не реальные активы)
**1. Полные данные.** Монета SYNTH-A: ранг 40 из 2000, объём 5·10⁷ $, оборот 0.08, 7д = −12 %, один источник.
ранг: 100·(1−ln40/ln2001)=51; объём: (lg5·10⁷−3)/7·100=67; significance=0.6·51+0.4·67=57.
interest=1.5·12+60·0.08=18+4.8=23. Признаков нет → `no_flags_seen`. trust: 5/5 полей·0.7=70.
Наблюдение 2 ч назад, ttl 24 ч → freshness 100. attention=57.
**2. Отсутствуют данные.** Проект SYNTH-B: нет TVL и изменения за 7д, аудит не указан, есть url.
Сейчас: significance 0, interest 0, флаг «аудит не указан». v2: significance `null`, interest `null`,
danger `unknown` (аудит не указан — отсутствие данных, не флаг). trust: 2/5·0.7=28. attention не считается.
**3. Устаревшие данные.** Как пример 1, но наблюдение 48 ч назад, ttl 24 ч: 100·(1−24/48)=50,
состояние `stale`. Значения показываются с пометкой; в порядок показа идут после свежих.
**4. Индикатор угрозы.** Проект SYNTH-C, домен которого (условный, не показывается) найден в двух
независимых списках, и во взломах за 30 дней: danger=`flagged`, 2·50+30 → min(100,130)=100.
significance и interest считаются обычным образом из рыночных данных; trust отражает только полноту
данных, а не опасность. Сами записи списков угроз в каталог как активы не попадают.
**5. Акция без подтверждённой сферы.** SYNTH-D: позиция 3000 из 7988 в списке SEC, сфера «не определена».
ранг: 100·(1−ln3000/ln7989)=11, `basis: proxy` (это место в файле, не размер компании).
interest `null` (бесплатного ряда цен нет). Тикера нет в справочнике Nasdaq → статус `unknown`,
danger `unknown`. trust: 4/5·0.7=56. Сфера остаётся «не определена», не додумывается.

## 8. Альтернативы и компромиссы
| Вариант | Плюс | Минус |
| --- | --- | --- |
| Один составной балл | просто сортировать | прячет «неизвестно» и причины |
| Взвешенная сумма факторов | один порядок | веса произвольны, без исходов не проверить |
| Модель по разметке (ML) | возможна точность | нет разметки исходов, нужна проверка, объяснимость хуже |
| **Факторы с состояниями (выбрано)** | честно про пробелы, объяснимо | больше полей, потребители обрабатывают `null` |
Риски: веса и ttl подобраны вручную; прокси для акций слабое; бесплатные источники нестабильны.
